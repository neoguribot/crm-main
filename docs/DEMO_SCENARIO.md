# 발표 시나리오 (DEMO_SCENARIO)

- 전제:
  - `docs/DEMO_DATA.md` 대로 샘플 데이터 적용 완료 (고객 50명, 거래 다수, 일정 약 16건 —
    절차적으로 생성되므로 이름·정확한 건수는 매번 다르다. 이름을 미리 외워서 시연하지
    않는다 — 아래 각 장면은 **필터·조건으로 고객을 찾는** 방식으로 구성했다)
  - **데모 계정 준비 여부**: 이메일·비밀번호를 미리 확인해 둔다 (값은 여기 적지 않는다).
    로그인 실패에 대비해 대체 계정도 하나 준비.
  - 상단 **공통 네비게이션**(홈 · 고객관리 · 거래관리 · 시세관리 · 캘린더 · 종합분석 · 로그아웃)으로 이동 가능.
- 총 7개 장면, 각 30~50초, 합계 약 5분

## 발표 전 준비 (탭·화면)

1. `npm run dev` 실행 (또는 `npm run build && npm run start`), http://localhost:3000 확인
2. 브라우저 탭 **1개만** 열어둔다: `http://localhost:3000/login` (로그아웃 상태)
3. 창 폭은 발표용 노트북 기준으로 넓게 (대시보드 카드가 여러 열로 보이는 너비)
4. 개발자 도구·불필요한 확장 프로그램 창은 닫는다
5. 입력할 값(아래 장면 3)을 손 닿는 곳에 메모

## 장면 0 · 로그인 + 홈 대시보드 (~40초)

- **클릭**: http://localhost:3000 → (미인증이면) 로그인 화면 → 이메일·비밀번호 입력 → 로그인
- **이동**: `/home` (기본 화면)
- **짚을 것**:
  - "오늘의 고객 관리 일정" 위젯 — 탭(오늘/기한 지남/7일 이내)으로 바로 필터링. 항목마다
    고객명·종류·날짜·남은(지난) 일자·메모 미리보기가 보인다.
  - "거래 수 현황" 표 — 오늘/어제/진행 중/완료(크게) + 이번 주/이번 달/올해 누적(작게),
    전부 거래 건수 기준(거래 고객 수 아님)
  - 이번 달 매출 지표(판매/매입 금액과 총 매출액)와 목표 도달 현황(현재값 = 판매+매입
    합산, 목표값은 홈에서 바로 수정 가능)
  - "방문 목적별 고객 수" 옆의 전체/오늘/이번 주/이번 달/올해 탭 전환
- **대사**: "금거래소 사장님이 쓰는 CRM입니다. 로그인하면 홈 화면에 오늘 챙겨야 할 일정과
  매출 지표, 목표 도달 현황이 한 화면에 모여 있습니다."

## 장면 1 · 고객 검색·세그먼트 (~50초)

- **클릭**: 상단 네비게이션 **고객관리** (또는 홈 "전체 고객" 카드) → `/customers`
- **시연**:
  1. 방문목적 체크박스에서 **매입** 체크 → 검색 (매입 위주 고객이 절반 이상 나오는 걸 확인)
  2. 여기에 빈도 라벨 **단골** 체크박스 추가 → 결과가 줄어드는 걸 보여준다(상단 조건 Badge 2개)
  3. "전체 초기화"
  4. 방문일 구간을 달력 팝오버로 선택해 오래 방문 안 한 고객 조회
  5. 매출 라벨 **VIP** 체크 → 큰손 투자 고객만 좁혀서 조회
  6. "연락처 복사" 버튼 → 현재 목록의 이름+전화번호가 클립보드에 복사됨을 보여준다
  7. 새로고침 → 필터 그대로 (URL 파라미터)
- **대사**: "이름은 정확히, 연락처는 하이픈 없이도 검색됩니다. 방문목적·유입경로·빈도/매출
  라벨은 체크박스라 여러 값을 한 번에 묶어서 찾을 수 있고, 방문일 구간까지 조합해서
  세그먼트를 바로 뽑고, 그 목록을 통째로 복사해 문자 발송에 바로 쓸 수 있습니다."

## 장면 2 · 고객 상세 — 라벨·지표·일정·거래 이력 (~45초)

- **클릭**: 장면 1 에서 찾은 고객(빈도=단골 + 매출=VIP 등 거래가 여러 건 있는 고객) 클릭 → 상세
- **짚을 것**:
  - 고객 정보에 성별·**빈도 라벨**(신규/단골)·**매출 라벨**(일반/우수/VIP) — 각각 자동
    추천 배지 함께 표시(빈도는 누적 거래 횟수, 매출은 최근 3개월 거래액 기준)
  - **추천인**(있으면 그 고객 상세로 링크) — 수정 화면에서는 이름/전화번호를 입력하면
    실시간으로 후보가 좁혀지는 검색창으로 선택한다
  - **지표 카드** — 누적 매출액·거래 횟수·평균 재방문 주기(일)·두 라벨을 차트 없이
    숫자로만 표시(원본 요구사항의 "불필요한 차트·색상 최소화" 반영)
  - 거래 이력 — 거래일 내림차순, ▲판매/▼매입 구분, 완료 여부 표시. 매입 고객이면 치금·
    구제품 매입 위주, 골드바 고객이면 골드바 판매 위주로 품목이 몰려 있는 걸 보여준다
  - 일정 섹션 — 거래와 연동해 등록 가능(진행 중인 맞춤 주문 건 등)
  - "고객 정보 수정"에서 날짜 입력(등록일·첫 거래일자·마지막 연락일, 생년월일 제외)은
    직접 타이핑하거나 달력 아이콘을 눌러 팝오버에서 고를 수 있다
- **대사**: "라벨은 재방문 빈도와 매출 규모, 두 축을 따로 관리합니다. 자주 오지만 소액인
  고객과 어쩌다 오지만 큰 거래를 하는 고객을 구분해서 볼 수 있어요. 사장님이 직접
  정하시되, 참고용 자동 추천 배지를 함께 보여드립니다."

## 장면 3 · 고객 등록 + 거래 기록 (~50초)

- **클릭**: 네비게이션 **고객관리** → "신규 고객 등록"
- **입력할 신규 고객**:
  | 필드 | 값 |
  | --- | --- |
  | 이름 | `데모 발표고객` |
  | 연락처 | `01099998888` (→ 자동으로 `010-9999-8888`) |
  | 성별 | 여성 |
  | 유입경로 | 네이버플레이스 |
  | 방문목적 | 주얼리 맞춤 + 골드바 (2개 체크) |
  | 고객 등록일 | 오늘 |
- **저장** → 생성된 상세로 이동
- **클릭**: 상세에서 "거래 기록 추가"
- **입력할 거래**:
  | 필드 | 값 |
  | --- | --- |
  | 거래구분 | 판매 |
  | 품목 | 24K(주얼리) |
  | 중량 | `5.2` |
  | 기준 단가 | `237,000` |
  | 총 금액 | `1,232,400` |
  | 완료 여부 | 완료 |
  | 거래일 | 오늘 |
- **저장** → 상세 하단 거래 이력에 표시, **마지막 연락일과 첫 거래일자가 자동으로 오늘로
  갱신**됨을 짚는다(이 고객의 첫 거래이므로).
- **대사**: "연락처는 입력하면 하이픈이 자동으로 붙습니다. 거래를 등록하면 마지막 연락일과
  (첫 거래라면) 첫 거래일자가 자동으로 갱신됩니다. 금액·중량은 소수점이 깨지지 않게
  문자열로 다룹니다. 매장에서는 순금 주얼리만 취급해서 18K·14K는 판매 품목에 없고,
  매입으로 들어온 구제품에서만 나옵니다."

## 장면 4 · 거래관리 + 시세관리 (~50초)

- **클릭**: 네비게이션 **거래관리** → `/transactions`
- **시연**: 검색창에 `010-9900` (샘플 고객 전화번호 앞자리 — 부분 일치) → 샘플 거래가
  여러 건 뜨는 걸 확인(날짜·구분·완료여부·이름·품목·단가·중량·총 금액·비고가 열
  맞춰 표시됨). 거래구분/완료여부 셀렉트에 "전체" 옵션이 있음을 보여준다. 거래일
  구간을 달력 팝오버로 좁혀서 검색(예: 최근 1개월). "신규 거래 등록" 버튼으로
  고객을 이름/전화번호 검색 콤보박스로 골라 거래를 새로 등록할 수도 있음을
  보여준다(거래일도 달력 팝오버). 목록의 "수정" 버튼 → 상세에서 수정·삭제.
- **클릭**: 네비게이션 **시세관리** → `/prices`
- **시연**: 상단 벨 아이콘에 샘플 데이터로 미리 만들어 둔 알림이 몇 건 있는 걸 먼저
  보여준다. 오늘 시세(24K 1돈 약 585,000원 안팎)를 새로 등록(등록할 때마다 이력으로
  쌓임, 하루에 여러 번 등록 가능) → 매수 희망가가 그 근처로 미리 설정된 샘플 고객이
  있어서 실시간으로 새 알림이 생성되는 걸 보여줄 수 있다. 시세 이력 목록에서 과거 값
  수정도 가능.
- **대사**: "거래는 고객 상세뿐 아니라 거래관리 화면에서 전체를 검색·수정·삭제할 수 있습니다.
  시세는 변동값이라 등록할 때마다 새 이력으로 쌓이고, 매수 희망가에 도달하면 알림이 뜹니다."

## 장면 5 · 캘린더 + 종합분석 (~50초)

- **클릭**: 네비게이션 **캘린더** → `/calendar`
- **짚을 것**: 이번 달 그리드에서 일정이 있는 날짜에 종류·고객명 미리보기, 클릭하면 하단에
  상세 목록. 상단 가운데 "○○○○년 ○월" 라벨을 클릭하면 팝오버로 연/월을 바로 골라
  이동할 수 있다(이전/다음 달 버튼 없이 몇 달을 건너뛸 때 유용).
- **클릭**: 네비게이션 **종합분석** → `/analytics`
- **짚을 것**: 왼쪽 열에 성별·연령대·유입경로 분포(여성이 대부분, 40~50대가 최다인 게
  보인다), 오른쪽 열에 빈도 라벨·매출 라벨 분포에 이어 **방문 목적별 평균 방문 빈도**
  (목적별 평균 거래 횟수와 전체 평균 대비 비율)와 **품목 분포**(품목별 누적 거래 수,
  판매 쪽엔 18K/14K가 없고 매입 쪽에만 있는 걸 확인할 수 있다)를 보여준다. 아래에는
  누적 거래액 상위 고객과 **누적 거래 수 상위 고객** 랭킹을 나란히 보여준다(집계는
  모두 DB에서 계산).
- **대사**: "캘린더로 한 달 일정을 한눈에 보고, 종합분석에서 고객 구성과 매출 기여도가 높은
  고객, 그리고 어떤 목적의 고객이 얼마나 자주 오는지까지 확인합니다. 매입 비중이 크고
  40~50대 여성 고객이 중심이라는 저희 매장 특성이 데이터로도 그대로 드러납니다."

## 오류 시 대체 흐름

| 문제 | 대체 |
| --- | --- |
| 홈 화면이 오류 카드 | `select public.dashboard_summary();` 를 SQL Editor 에서 실행해 확인. 안 되면 `0015`/`0021`/`0024` 마이그레이션 재적용 |
| 종합분석 화면이 오류 카드 | `select public.customer_analytics();` 로 확인. 안 되면 `0018`/`0019`/`0025` 마이그레이션 재적용 |
| 신규 고객 등록이 실패 | 이미 있는 샘플 고객 아무나로 장면 3의 "거래 등록"만 진행 |
| 거래 등록이 실패 | 거래 이력이 있는 샘플 고객 상세로 바로 이동해 장면 2 로 진행 |
| 홈 일정 위젯이 비어 보임 | 샘플 적용 후 시간이 많이 지났을 수 있음 → `demo_data.sql` 재실행(날짜가 오늘 기준으로 다시 계산되고, 일정도 새로 생성됨) |
| 검색 결과가 예상과 다름 | 필터 Badge 를 모두 지우고 다시 하나씩. `?` 뒤 파라미터 오타 확인. 샘플은 무작위 생성이라 정확한 인원수는 매번 다를 수 있음 |
| 로그인이 안 됨 | Supabase > Authentication > Users 에서 비밀번호 재설정, 또는 새 테스트 사용자 생성 후 `demo_data.sql` 을 그 UUID 로 재적용 |
| 화면이 깨짐 | `npm run build` 후 `npm run start` 로 프로덕션 모드 사용 |

## 발표 중 절대 하지 말 것

- 실제 고객 데이터 입력 (샘플만 사용)
- 샘플 제거 SQL 실행
- Supabase 대시보드에서 RLS 끄기
- `.env.local` / 키 화면 노출
